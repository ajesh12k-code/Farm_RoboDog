# Simulator fidelity register

Status: draft. Requirements: a fidelity register (per sensor and actuator: faithful, approximated or not simulated) and a cannot-prove list (documentation states what the simulator cannot prove). Risk addressed: the simulator treated as proof of what it cannot prove.

Ratings: **faithful** (the sim models the physics or behaviour well enough that a pass is meaningful for that item), **approximated** (modelled, with known simplifications; a pass is a hint), **not simulated** (absent; a sim result says nothing). Model values are read from `atharv_nandi/sim/models/AtharvNandi/atharv_nandi.xml`, `atharv_nandi/core/farm_scene.py` and the orchard modules on `feat/nandi-pilot` @ 1840118 (code).

WP12 (2026-11-18) re-rated the base rows for the orchard MVP and added section 2, the **assisted register** (ORCHARD-MVP-SPEC 3.9 plus every assisted tag the code emits and every row the work packages asked for). `tests/test_design_docs.py` checks that every row carries one of the three ratings and that the eight base items have a row; `tests/test_wp12_docs.py` checks that every assisted tag the code puts on a run card, a record or a status (`assisted: [...]`) has a row in section 2. A machine-readable JSON copy is a follow-up, not done.

## 2 Assisted register

An assisted item replaces a sensor, a contact or a controller with truth, a weld or a kinematic shortcut, so the robot does something the physics alone would not show. Each one used in a run is listed on that run's card (`assisted[]`) and next to every KPI it touches (WP9 `scope_kpi.py`). Status: **[BUILT]** = the tag is a string in code; **[BUILT, no tag]** = the behaviour is in code but no record carries the tag yet (the row comes from a work-package fragment); **[OS 3.9]** = named by the spec as a register entry (it may be applied by construction without a tag string); **[PROPOSED]** = requested for a package that has not landed.

## 3 What the simulator cannot prove (cannot-prove list list, applied to Nandi)

RF range, soil and water behaviour, water ingress, enclosure heat, real current draw, Jetson and Hailo speed: none of these is simulated for Nandi (rows above). For the orchard MVP add: crown sway and snag forces, foliage occlusion of LiDAR, foliage and fruit motion in wind, worker and animal behaviour, and detection on real imagery. A pilot report that uses sim numbers must say so next to each number and list the run card's assisted items with it.
